The Challenge

Problem Statement

Turning 20 Million Raw Flight Logs into Actionable Real-Time Insights.

🔗

The Raw Reality

Operational flight data is massive (8.7GB+), messy, and disconnected across raw logs, making operational bottlenecks invisible.

📍

The Consequence

Unidentified delay causes (carrier vs. weather vs. late aircraft) result in major revenue losses and poor passenger experience.

⚠️

Raw Data is Unusable Without Processing

Flight data is fragmented and difficult to process, while many carriers lack the technical resources to convert raw logs into actionable insights.

💡

No Intelligent Decision Support for Airline Teams

Most airline operations teams lack AI-powered tools to turn flight data into practical decisions for scheduling, crew planning, and delay prediction.

The Answer

Our Unified Intelligence Platform

A fully automated, containerized system that orchestrates flight data end-to-end, from raw ingestion to real-time operational intelligence.

🔄

End-to-End Pipeline Cohesion

Seamlessly orchestrates data flow from raw storage (HDFS) and event brokers (Kafka) through Spark down to PostgreSQL data marts using Apache Airflow.

⚙️

Optimized Storage & Compute

Replaces heavy, uncompressed raw CSV scans with schema-enforced, partitioned Parquet files to minimize disk I/O and query latency.

📊

Dual-Layer Decision Support

Delivers both macro-level diagnostic analytics (root-cause delay breakdowns, route reliability) and live operational monitoring (real-time delay spikes and status updates).

How It Works

The Data Pipeline

🐳

Docker Infrastructure Setup

Our core infrastructure is containerized using Docker & Docker Compose on a shared bridge network (airline-net). Services including ZooKeeper, Kafka, PostgreSQL (airline_db), Apache Airflow, and Apache Superset run in isolated containers to ensure seamless integration between batch and streaming layers.

1

Ingestion & Verification

Batch & Stream

Airflow verifies historical BTS flight CSV files (~8.7GB) in HDFS under /skylens/raw/flights using a lightweight Python client. In parallel, a Python Flight Producer streams real-time flight status JSON events directly into Kafka (flight-events topic).

2

Connection & Stream Initialization

Smoke Test & Micro-Batches

Spark executes a fast smoke test reading HDFS raw files to validate batch schema parsing, while Spark Structured Streaming subscribes to the Kafka topic to read the live event micro-batches.

3

Cleansing & Schema Enforcement

Validation & Deduplication

PySpark enforces explicit schemas on batch data, filters missing/corrupted records, and deduplicates 20.6M+ rows into compressed Parquet. Simultaneously, Spark Streaming parses live Kafka JSON payloads and converts timestamp fields on the fly.

4

Enrichment & Feature Engineering

Attributes & Partitioning

Spark derives temporal attributes (Year, Month, Season), delay flags (IsDelayed), composite RouteID, and identifies the PrimaryDelayReason, writing partitioned batch data by Year/Month.

5

Aggregation & Micro-Batch Processing

OLAP Models & Stream Processing

Spark computes 5 historical OLAP models in memory (airlines, routes, airports, monthly trends, delay causes), while foreachBatch in Spark Streaming processes live micro-batches for real-time status updates.

6

Data Warehousing & Dual BI Dashboarding

PostgreSQL & Apache Superset

Batch aggregates and streaming micro-batches are persisted into PostgreSQL via JDBC (airline_db). Apache Superset connects directly to PostgreSQL to power both historical analytics and near-real-time operational dashboards.
